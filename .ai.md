## Non-Negotiable Invariants

1. **Continuous Doc API & OpenAPI Maintenance**: The [`.ai/doc-api.md`](.ai/doc-api.md) file and OpenAPI 3.1 specifications (`api/openapi/openapi.yaml`) MUST be kept updated on **every code change or addition**, regardless of how small the modification is.
2. **Secured Logging**: All logging must be structured JSON. Strictly redact PII/PHI, client authorization headers, bearer tokens, AWS STS secrets, and presigned S3 URLs (specifically query string signatures `X-Amz-Signature`) before emission.
3. **Pure Control Plane Orchestration**: Drive complex multimodal ingestion workflows via Temporal without buffering, parsing, or streaming binary payloads or columnar Arrow buffers through the coordinator.
4. **Zero-Heap Ingestion & Flat Memory Ceiling**: Strictly maintain $<256\text{ MiB}$ resident set size (RSS) per pod, regardless of incoming file size (tested up to 10 GB monolithic uploads).
5. **Polyglot Activity Scheduling**: Coordinate language-specialized workers (Go for storage/metadata, Python for Document AI/Docling/OCR/ASR) using native Temporal task queues (`inspection-queue`, `doc-ai-queue`, `chunk-lifecycle-queue`), decoupling task execution from synchronous transport protocols.
6. **Resilient Child Workflow Execution**: Isolate document slice executions into independent `DocumentPartitionWorkflow` child workflows to prevent event history exhaustion on multi-gigabyte or high-page-count documents ($<10,000$ events per execution history).
7. **Single Source of Truth for State (Zero Dual-Writes)**: Rely solely on Temporal workflow state and heartbeat payload details for in-flight task progress and crash recovery; write to PostgreSQL only at pipeline boundaries (`COMPLETED` or `FAILED`).
8. **Scalable Real-Time Telemetry**: Publish pipeline stage events asynchronously via Redis Pub/Sub to decouple ingestion coordination from client connection lifecycles.
9. **Deterministic S3 Artifact Namespaces**: Enforce idempotency on activity retries using content-addressed S3 path conventions: `s3://<bucket>/artifacts/<tenant_id>/<doc_hash>/slice_<start>_<end>.parquet`.
10. **Code Cleanliness & Quality Gates**: All Go code must pass `golangci-lint`, `go vet`, formatting checks (`gofmt -s`), and strict vulnerability audits (`govulncheck`, `gosec`).

## Git Commit Standards

- **Git Commit Frequency**: Commit code as you build. Every working session or phase must contain **at least two git commits**.
- **Conventional Commit Patterns**: All git commit messages must strictly adhere to the following prefixes:
  - `feat:` for new features 
  - `fix:` for bug fixes
  - `refactor:` for code refactoring
  - `docs:` for documentation updates
  - `tests:` for tests addition and modification
  - `chore:` for maintenance tasks and environment setup

---

## Pre-Commit Verification Rules

Before committing code, submitting changes, or marking a task complete:

1. Run Go formatting: `gofmt -s -w .`.
2. Run Go static analysis: `go vet ./...` and `golangci-lint run`.
3. Run test suites: `go test -v -race ./...`.
4. Verify [`.ai/doc-api.md`](.ai/doc-api.md) and `api/openapi/openapi.yaml` are updated with all API, schema, or storage modifications.
5. Verify Secured Logging rules: Ensure no AWS credentials, presigned query strings, bearer tokens, or PII are logged.
6. Update [`.ai/progress-tracker.md`](.ai/progress-tracker.md).
